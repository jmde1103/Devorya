1. 적용 내용
- 제공한 엑셀의 최종 적용 번역 128개 키 × ko/en/ja = 384개 번역을 기존 String Table에 반영.
- 기존 Localization 키/ID/GUID와 데이터 참조 유지. 연결 없는 레거시 11개 키도 삭제하지 않음.
- 데이터 Inspector의 한국어 fallback 필드 56개 동기화.
- 번역 원문에 색상 태그를 넣지 않음. 기존 String Table 항목의 TooltipSemanticMetadata에 강조할 구절과 의미만 기록.
- 툴팁 표시 시에만 표준 TMP color 태그로 변환. 일반 안내창·유물 카드의 번역 getter는 원래처럼 일반 문자열 반환.
- 제목: 흰색 굵게. 본문: 회색 보통. 분류/보조: 짙은 회색.
- 긍정 효과: 청록. 부정 효과: 붉은색. 수치: 노랑.
- 상태효과 하단 섹션 제목은 해당 효과 분류 색상 + 굵게.
- 기존 본문 자동 높이 유지. 퇴화 설명에서 발견한 하단 섹션 잘림을 수정해 섹션과 배경도 아래로 확장.
- 기존 Hierarchy, 프리팹 연결, 아이콘·헤더의 배치와 오픈 애니메이션 사용 방식 유지.
- 이 툴팁 경로에는 별도 글자 단위 타이핑이 없어 타이핑 코드를 새로 넣지 않음.

2. 실제 게임 동작을 확인하여 문서와 다르게 적용한 부분
부러진 방패:
  실제 아이템 효과 목록에는 방어 한 개만 연결되어 있음.
  '선택한 아군 기물에게 [방어]를 1턴 동안 부여합니다.'로 세 언어 보정.
  행동불가를 새로 부여하도록 게임 효과를 변경하지 않음.
분열:
  원래 위치 1개 + 인접한 빈칸 1개 = 총 2개 생성 확인. 제공 문구 그대로 적용.
퇴화:
  일반 전투 처치/흡수 및 마무리 흡수 제거 경로에서 호출됨.
  모든 RemovePiece 호출이나 합성 재료 제거에 일괄 발동하는 구조가 아님.
  '공격 또는 흡수로 제거되면'으로 세 언어 보정.
  인접한 빈칸과 팀 최대 기물 수 조건은 기존 코드 유지.

4. 이후 번역·데이터 작성 방법
- 기존 데이터 Inspector 또는 Localization String Table의 기존 키에서 번역을 수정.
- 시스템명: 한국어·영어 [이름], 일본어 ［名前］. 제목에는 괄호를 넣지 않음.
- 강조하려면 해당 언어 String Table Entry의 Metadata에 TooltipSemanticMetadata를 추가.
- spans에 강조할 원문 구절과 역할(긍정 효과/부정 효과/수치)을 지정.
  예: [방어] → 긍정 효과, [공격불가] → 부정 효과, 1턴 → 수치.
  영어/일본어도 각 번역에 실제 포함된 구절을 등록.
- 특성의 동적 확률은 {percent}% 또는 {value}를 원문 그대로 지정 가능.
- 색상 코드 자체를 데이터나 번역에 반복해서 넣지 않음.
- 메타데이터가 없는 기존 항목은 일반 본문 색으로 정상 표시.
- 번역에서 강조 구절을 바꿨다면 Metadata의 구절도 함께 변경해야 함.
- 모든 숫자나 한국어 단어를 런타임에서 추측해 색칠하지 않음.
- 기존 TMP rich text는 유지하며, 태그 내부에 색상 태그를 끼워 넣지 않음.
- 작업용 엑셀 입력 변환 자료는 Logs/tooltip-translation-input.json이며 런타임 번역 저장소가 아님.
