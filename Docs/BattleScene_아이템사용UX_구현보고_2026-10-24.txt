KR/EN/JA는 Battle_UI의 battle.ui.item.select_target 키로 관리한다.

아이템 확인용 초록색은 별도 API로 표시한다. 일반 이동·공격의 확인 색상은 유지한다.
PC와 모바일은 기존 PixelCameraController의 SelectTile 전달 경로를 계속 사용한다. Tile.OnMouseDown에 새로운 입력 처리를 추가하지 않았다.
동일 프레임 중복 전달 및 효과 실행 중 재진입을 차단한다.

3. 효과 검증과 소모
ValidateItemEffect는 기물이나 아이템, 상태효과, RunState, 난수를 변경하지 않는다.
단일/복합 효과에 동일한 검증을 사용한다.
검사 항목: 유효한 활성 대상과 보드 등록, 플레이어 전용, 킹 제한, 상태 데이터, 해제할 상태 존재, 변환 데이터, 추가 이동 가능 여부.
변환 후 추가 이동은 변환될 타입을 전달해 실제 이동 판정기를 사용한다.
중복 상태 제거, 추가 이동 중복, 선행 이동 제한 등 실행 도중 실패할 수 있는 조합을 사전 거부한다.
새로 부여하는 상태는 저항으로 부여되지 않을 수 있으므로, 이를 후속 해제 효과의 확정 전제조건으로 취급하지 않는다.
복합 효과의 추가 이동 선택/UI 갱신은 목록 적용 후 수행한다.
선택 당시 인벤토리 버전·아이템 참조와 RunState의 목록을 재확인한다.
효과 성공 후에만 해당 슬롯 제거 → 슬롯 압축 → UI 갱신을 실행한다.

4. 취소 및 예외 처리
같은 슬롯 재클릭: 취소.
공용 배치 확인/마무리 흡수 버튼: 아이템 선택 중에는 X 취소 버튼으로 전환.
취소 버튼을 눌렀을 때는 배치 완료·마무리 흡수·일반 흡수 입력으로 넘어가지 않는다.
아이템 모드에서는 마무리 흡수 파티클·펄스를 중지하고 흡수 툴팁을 숨긴다.
모드 종료 시 배치 체크/일반 흡수 아이콘을 복구한다. 마무리 흡수 가능 상태였다면 해당 버튼과 강조 연출도 복구한다.
아이템 선택 중 발생한 마무리 흡수 상태 변경은 기억하되 취소 버튼의 X 아이콘과 동작을 유지한다.
다른 슬롯: 기존 선택 해제 후 새 후보 계산.
다른 대상: 기존 확인 타일을 파랑으로 되돌리고 새 대상을 초록색으로 표시.
빈 타일: 선택 유지.
유효하지 않은 대상: 사유 팝업, 소모 없음, 후보 재계산.
대상 소실: 확인 상태 제거 및 후보 재계산.
슬롯/인벤토리 변경: 취소 및 사유 안내.
ESC/우클릭: 취소. 모바일에서는 같은 슬롯 재탭으로 취소.
턴 종료, 적 턴, 행동 연출, 이벤트 강제 입력, 전투 종료, 오브젝트 비활성화 시 정리.
사용 가능 대상 0명: 모드에 진입하지 않고 사유 안내.
기존 SkillFailurePopup의 표시·페이드 처리를 사용한다.

5. API와 호환성
BattleManager.UseItemAtSlot(int), BattleItemManager.UseItemAtSlot(int)는 유지하되 대상 선택 모드 진입으로 동작한다.
BattleManager.TryApplyBattleItemEffect(BattleItemData)의 기존 bool API는 유지한다.
명시적 Piece를 받는 TryApplyBattleItemEffect(BattleItemData, Piece)를 추가했다.
BattleItemEffectHandler.TryApplyItemEffect(BattleItemData, Piece)의 bool API를 유지한다.
실패 코드를 반환하는 ValidateItemEffect와 out 실패 코드를 받는 실행 API를 추가했다.
기존 이동 판정 API의 호출 방식은 유지하며 선택적인 예상 PieceType 인수를 추가했다.
기존 SerializeField, UnityEvent 연결, enum 값, 에셋 GUID를 변경하지 않았다.
기존 CP949 파일은 해당 인코딩으로 저장했고 신규 코드는 UTF-8이다.

9. 미검증 사항과 한계
실제 PC 사용자의 마우스 조작 및 모바일 실기기 터치/빌드는 수행하지 않았다.
자동 검증은 PC·모바일이 공유하는 SelectTile 진입점을 호출했다. 실제 포인터/터치 이벤트 전체를 재현한 것은 아니다.
ESC/우클릭은 입력 처리 코드를 연결했지만 실제 하드웨어 입력으로 자동 검증하지 않았다.
슬롯 점멸의 육안 가독성, 모든 해상도, WorldMap 전체 흐름, 모든 튜토리얼/씬 전환 조합은 별도 육안 확인이 필요하다.
새 복합 효과 종류를 추가할 경우 공통 사전 검증도 함께 확장해야 한다.
현재 효과 유형의 알려진 실패 조건은 사전 차단하지만, 임의의 외부 스크립트 예외까지 복원하는 범용 트랜잭션/롤백 시스템은 추가하지 않았다.
검증 중 생성한 기물과 아이템은 테스트 플레이에만 존재하며 씬/데이터 에셋으로 저장하지 않았다.

10. 현재 작업 트리 참고
BattleScene.unity에는 테스트 스테이지 참조 변경과 기존 아이템 확인 색상/강도 필드 직렬화가 발견되었다. 이번 취소 버튼 코드에서는 씬 저장이나 테스트 스테이지 참조 변경을 수행하지 않았으며, 해당 변경은 되돌리지 않고 보존했다.
